# The transformer: Attention is all you need

In 2017, a team at Google working on machine translation published a paper with an unusually cocky title: [Attention Is All You Need](https://arxiv.org/abs/1706.03762). The claim was that the attention mechanism — until then a bolt-on that helped RNNs translate — could replace recurrence entirely. The resulting architecture, the **transformer**, is the substance of every model in this book. GPT stands for Generative Pre-trained *Transformer*, and nine years later the architecture is nearly unchanged.

Chapter 2 left a network-shaped hole: something has to read the context's embedding vectors and produce the next-token logits. This chapter fills it, in three steps:

1. The RNNs that held the job crushed the whole past into one fixed-size vector and processed tokens one at a time. We need a network that keeps *every* token's vector and reads them all at once.
2. One new primitive does it — **attention**: a differentiable lookup in which every token fetches what it needs from the tokens before it.
3. Alternate attention with Chapter 1's MLP along a residual stream, stack it deep, and you have a GPT. Everything since is this, scaled.

## The problem attention solves

Recall the RNN's two flaws. Squeezing an arbitrarily long past into one fixed-size hidden state meant long-range information got crushed — by the end of a page, the beginning had been averaged into mush. And the recurrence itself — each step consuming the previous step's output — meant the computation was inherently *serial*: token 1,000 could not be processed until tokens 1 through 999 had been, no matter how much hardware you owned.

Start from what Chapter 2 handed us: after the embedding lookup, the context already *is* a list of vectors — one per token. The RNN's defining decision was to fold that list, token by token, into a single running summary — and the first flaw is that decision's direct price: a thousand tokens of detail forced through one $d$-dimensional keyhole. So consider the opposite decision: **don't fold.** Keep all $n$ vectors, and refine them in *rounds*. You've seen this organization before: Chapter 1's MLP was built from stacked **layers**, each one taking the previous layer's output and transforming it. The transformer keeps the word and scales up the unit — here, a layer takes all $n$ token vectors in and hands all $n$ vectors back, each one refined (what exactly happens inside a layer is this chapter's remaining business). Stack a few dozen layers and token 500's vector stays token 500's vector all the way up the building — just getting smarter at every floor.

But refusing to summarize creates a problem the RNN never had. If every token keeps its own vector, how does information move *between* them at all? In "the cat sat … because it was tired," the vector for "it" is useless until something from "cat" gets into it — and which other tokens matter differs for every token, every sentence. We need a mechanism by which each token's vector can reach into the rest of the context and pull in what's relevant, *selectively*, with the selection itself learned. That mechanism is this chapter's one invention.

The second flaw dies as a side effect of the first decision. Each token's update depends only on the *previous layer's* vectors — never on another token's output at the same layer — so every position can be computed **simultaneously**. That quiet property is the one that decided history: it let the architecture absorb all the parallel hardware money could buy, which is the subject of the next chapter — and of Chapter 10, where we meet the hardware itself.

## Attention: a differentiable lookup

Each token's current vector is linearly projected into three new vectors, whose names tell you the whole story:

- a **query** $q$ — "what am I looking for?"
- a **key** $k$ — "what can I be found by?"
- a **value** $v$ — "what information do I carry?"

To update a token, take its query and dot it against every earlier token's key — a big dot product means "relevant to me." Softmax the scores into weights, then average the earlier tokens' *values* using those weights. It's a **hash map with soft lookups**: a normal map retrieves exactly one value per key; attention retrieves *every* value at once, weighted by how well each key matches the query. And because queries, keys, and values are all produced by learned matrices, gradient descent decides what each token should ask for, advertise, and carry.

Here's the entire lookup with real numbers, small enough to check by hand — watch the pronoun "it" go looking for its noun:

<AttentionStepFigure />

In symbols, with all tokens stacked into matrices, the whole thing is one line:

$$
\mathrm{Attention}(Q, K, V) = \tip{turn relevance scores into weights that sum to 1}{\mathrm{softmax}}\!\left(\frac{\tip{every query dotted with every key: how relevant is each token to each other token}{QK^\top}}{\tip{keeps scores from growing with vector size and saturating the softmax}{\sqrt{d_k}}}\right) \tip{the weighted average of the values — what actually gets retrieved}{V}
$$

And in code, it's a handful of matrix multiplies:

```python showLineNumbers
def attention(x, W_q, W_k, W_v):     # x: (seq_len, d_model)
    Q, K, V = x @ W_q, x @ W_k, x @ W_v
    scores = Q @ K.T / math.sqrt(K.shape[-1])   # (seq_len, seq_len)
    scores = causal_mask(scores)     # -inf above the diagonal
    return softmax(scores, axis=-1) @ V
```

Two lines of that snippet deserve their own sections.

## Look back, never forward

During training, all positions are computed at once — which means position 5 could "cheat" by attending to position 6 and reading the future it's supposed to predict. The **causal mask** prevents it: before the softmax, every score where a token would look *forward* is set to $-\infty$, so the softmax assigns it exactly zero weight.

<CausalMaskFigure />

This mask is what makes the model **autoregressive** — a term borrowed from time-series statistics whose etymology *is* its definition: *auto-* (self) + *regression* (the first tool this book reached for, back in Chapter 1). An autoregressive model regresses a sequence *on itself* — each value predicted from the values before it. Statisticians have fit autoregressive models to stock prices and weather for a century; a GPT is the same idea with a trillion-parameter regressor and tokens for data points. The mask is what enforces the "before": each token predicts while seeing only its past.

The mask is also what makes training spectacularly efficient: every position in the sequence becomes its own training example (predict token 2 from token 1, token 3 from tokens 1–2, …), and the mask lets all of them be computed in a single parallel pass. One sentence in, hundreds of next-token exercises out.

The figure also shows the architecture's famous tax. That score matrix has one cell per query–key pair: $n$ tokens means $n^2$ cells, so doubling the context quadruples attention's cost. This is why models advertise a **context window** — a maximum sequence length — and why long context is expensive enough that Chapters 5, 10, and 11 all spend time fighting the quadratic.

## Many heads, many questions

One soft lookup per token is not enough. Resolving "it" needs one kind of question; tracking whether we're inside a quotation needs another; matching a closing bracket in code needs a third. So the mechanism is run many times in parallel: each **head** gets its own (smaller) learned $W_q, W_k, W_v$, performs its own lookup, and the results are concatenated. A single attention operation in a frontier model runs on the order of a hundred heads side by side — and the full model, as we'll assemble in a moment, stacks on the order of a hundred such operations.

<AttentionFigure />

Heads learn their jobs the way all network weights do: gradient descent, nothing more. Some of what they learn turns out to be legible after the fact — previous-token heads like the one above are among the best-documented circuits in interpretability (Chapter 6 tells that story).

## Attention is a set operation

Look at the code again: nothing in it knows *where* a token is. Shuffle the keys and values and every output is unchanged — attention treats the context as a *set*, not a sequence. "The cat chased the dog" and "the dog chased the cat" would be indistinguishable. Word order has to be injected explicitly.

The fix is unglamorous: make position part of the input. The original paper computed a **positional encoding** — a vector that depends only on the position number — and *added* it to each token's embedding, so "cat as token 2" and "cat as token 9" enter the network as slightly different vectors, and attention can learn to care about the difference. Modern models use a cleverer scheme (**RoPE**) that encodes *relative* position — "three tokens back" rather than "position #4,821," which is what sentences actually care about. Its mechanics, and the tricks for stretching positions to million-token contexts, are Chapter 5's business.

## The MLP returns

Attention moves information *between* tokens, but does surprisingly little computation on it. So after each attention step, every token's vector is passed — independently, in parallel — through an MLP: the exact architecture from Chapter 1, typically expanding to 4× the model width and back down.

The division of labor is worth engraving: **attention routes, the MLP computes.** Attention gathers the relevant context into a token's vector; the MLP is where that vector gets *processed* — and, as Chapter 6 will show, where most of the model's factual knowledge appears to live. In a standard transformer the MLPs hold roughly two-thirds of the parameters. When people say "a bigger model knows more," they are mostly talking about MLP weights.

## One picture to keep

All the parts are on the table; here is the machine they make, in a single mental image — the computation as a *spreadsheet*. One column per token; the top row is the embeddings; each row below is all $n$ vectors after one more layer. Watch it build, one cell at a time, and watch what each cell reads:

<GridCellsFigure />

Every cell looked at exactly one place: the row above, columns up to its own. And notice what no cell ever read — a neighbor in its *own* row. Nothing within a layer depends on anything else within that layer, so there is nothing to wait for: an entire row can be computed in one parallel shot. Which is how it's actually done —

<KvGridFigure />

Two things this picture makes obvious. The next token always comes from the **bottom-right cell** — everything else exists to make that one cell smart. And generation just *appends a column*: the new token's cells are computed, and **no existing cell changes** — a finished column is finished forever. Which means each cell's keys and values can be stored and reused instead of recomputed. That store is the **KV cache**, the single most important fact of inference economics, and Chapter 11 is largely about it.

## The residual stream

Now zoom in on a single *column* of that spreadsheet — one token's vector, followed through the layers:

<StreamColumnFigure />

We can now say what's inside the "layer" promised at the chapter's start: one attention step plus one MLP — each preceded by a normalization step that keeps the vectors' magnitudes stable. That pair is called a **block** (papers use "block" and "layer" interchangeably): $n$ vectors in, $n$ refined vectors out. A model is a stack of them: 12 in GPT-2, on the order of a hundred in a frontier model. Crucially, each part doesn't *replace* the token's vector; it computes a modification and **adds** it:

$$
\tip{the token's residual stream}{x} \leftarrow x + \tip{reads the stream and writes back what it gathered from other tokens}{\mathrm{Attention}(x)}; \qquad x \leftarrow x + \tip{reads the stream and writes back what it computed on this token}{\mathrm{MLP}(x)}
$$

Make the addition concrete with the numbers from the attention walkthrough above. The token "it" entered attention as $x = [0, 2]$. The lookup returned $[1.65, 0.31]$ — mostly cat's vector. The update *adds*:

$$
x_{\text{new}} = \tip{whatever 'it' already was — still in there}{[0, 2]} + \tip{what attention fetched — mostly cat}{[1.65,\ 0.31]} = [1.65,\ 2.31]
$$

Look at what addition preserved. The original $[0, 2]$ — everything "it" already was (a pronoun, in subject position) — is *still in the vector*, now joined by cat-ness. If the block had **replaced** the vector instead, the pronoun would have been overwritten by the cat; because it **adds**, the token accumulates. The MLP then reads the combined vector and adds its own contribution — perhaps, having seen "pronoun + cat + tired" together, something like *sleepy animal*. A later block's attention can read *that* and route it to other tokens. Each token's vector only ever gets richer.

That accumulating vector is the **residual stream**, and the mental model — standard in the interpretability field — is a shared memory bus: one stream per token, flowing up through the stack, with every attention head and every MLP *reading* from it, computing something, and *writing* the result back by addition:

<ResidualStreamFigure />

Early layers tend to write low-level features, middle layers concepts and facts, late layers whatever converts it all into a concrete prediction.

<details>
<summary>Why the addition also matters for training (not just for accumulating)</summary>

If blocks *replaced* the vector, backprop would still work — the chain rule composes through anything differentiable. The problem is magnitude. The gradient reaching layer 1 would be a product of a hundred consecutive layer-derivatives, and any systematic shrinkage in those factors compounds exponentially — by the bottom of the stack the signal is numerically zero, and the early layers stop learning (the "vanishing gradient" problem that stalled deep networks for years). With $x + f(x)$, each block's derivative is *identity plus something*: among all the paths the chain rule sums over, there's always one straight shot of plus signs from the loss to every layer, unattenuated. Hundred-block stacks are trainable because of it.

</details>

Here's the question that makes the whole arrangement click. Suppose the context said, pages ago, "Jack, a tall man with red hair, walked in" — and the model must now continue "Jack's hair was ___". A single attention lookup sounds hopeless for this: the token "hair" can attend back to "Jack," but the *token* "Jack" is just a name — the redness lives three tokens away, on "red." How can attending to unprocessed tokens answer a question whose answer is smeared across several of them?

It can't — and it never has to, because after the first block, **attention doesn't read tokens; it reads the previous layer's streams.** Somewhere in an early block, a head doing purely local work moved "red" into the stream above "Jack" — the column over that name now *contains* his hair color. By the time a late block's query from "hair was" goes looking for facts-about-Jack, the answer has already been computed and parked where the name is; retrieval is one hop because earlier layers did the assembly. That's what depth buys: each layer attends over the *results* of every layer below it, so one lookup becomes a pipeline of lookups over its own previous conclusions. The stream above a token isn't the token — it's the model's accumulating *dossier* on that position, and later layers consult dossiers, not words.

So here is the entire architecture, end to end:

1. Look up each token's **embedding** (Chapter 2).
2. Pass the sequence through N blocks of **attention → MLP**, each reading from and writing to the residual stream.
3. Project the final vector of the *last* token onto the vocabulary to get **logits**, softmax into a distribution (Chapters 1–2), and predict.

That's it. There is no module labeled "grammar," no knowledge base, no planner. Everything a frontier model does is implemented in the weights of these identical, repeated blocks — which is either deeply unsatisfying or the most interesting fact in computer science, depending on your mood.

<details>
<summary>Where do the parameters actually go? GPT-2, counted.</summary>

GPT-2 shipped in four sizes; the smallest — plain "GPT-2", the 124M-parameter one — has width $d = 768$ and stacks 12 blocks. Per block: the four attention matrices ($W_q, W_k, W_v$, plus one to mix the heads' outputs back together) are $d \times d$ each — about $4d^2 \approx 2.4$M parameters. Heads, by the way, are free: this model runs 12 heads per block, each working in $768/12 = 64$ dimensions — the $d \times d$ matrices are simply *sliced* across them, so the head count changes the shape of the lookups but not the number of weights. The MLP expands to $4d$ and back: two matrices totaling $8d^2 \approx 4.7$M — the MLP is 2× attention, right there. Times 12 blocks ≈ 85M. Add the embedding matrix — 50,257 tokens × 768 ≈ 38.6M, shared with the output layer — and you land at ~124M, the number on the tin. Every transformer's parameter count decomposes this way, and you can now read any model's config file and check.

</details>

## The lineage that won

The 2017 paper had two towers — an encoder for the source language, a decoder for the target — and the years since sorted their descendants:

<LineageFigure />

[BERT](https://arxiv.org/abs/1810.04805)-style encoders powered search and classification. OpenAI's GPT line took the **decoder-only** path: just the causal stack described in this chapter, trained on next-token prediction. [GPT-2](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf) (2019) showed one such model could do many tasks without task-specific training; [GPT-3](https://arxiv.org/abs/2005.14165) (2020) showed what happens when you scale it 100× — which is the next chapter's story. Every frontier LLM today is decoder-only.
